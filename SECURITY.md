# Security Policy

This repository follows a coordinated disclosure process to ensure vulnerabilities are handled responsibly.

## Table of contents

- [Reporting a vulnerability](#reporting-a-vulnerability)
- [What to include](#what-to-include)
- [Response process](#response-process)
- [Contact](#contact)

## Reporting a vulnerability

Do not open a public issue for security vulnerabilities. Instead, contact the maintainers privately so we can investigate and coordinate disclosure.

Preferred reporting methods:

- Open a private issue and mark it "security" (if your GitHub plan supports private issues), or
- Contact the maintainers by email (maintainers may provide an address in the repository README).

## What to include

When reporting, please include:

- Affected component or package
- Steps to reproduce
- Impact and severity
- Any suggested mitigations

## Response process

We will acknowledge valid reports promptly and communicate a remediation plan and timeline. We may request additional information and coordinate a disclosure schedule.

## Contact

If you need to contact the maintainers privately, use the private issue flow or the maintainer email listed in the README.
